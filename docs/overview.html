roc-time

Build date calculations, availability queries and bounded schedules with explicit calendar and time-zone choices.

Choose a starting point

  • Civil dates: GregorianDate validates dates; CalendarArithmetic makes month-end policy explicit.
  • Availability: PosixSpan represents a nonempty interval; Coverage combines intervals and finds uncovered time.
  • Local appointments: LocalDateTime combines a date and clock label; ZoneRules interprets it with supplied data.
  • Schedules: DateRecurrence enumerates dates; TimedSchedule produces identified appointment spans.
  • Imported recurrence values: RfcDateRule supports a declared DATE-only RFC 5545 profile. Native timed constructors are separate.

Using the examples

Code blocks import modules through a package dependency named time. Add that name to your application's package header. The example applications show complete headers, effects and reporting. The expect lines demonstrate results; Roc runs them with roc test.

Constructors return Try for invalid input. Inside a function returning Try, ? forwards an error to its caller. Choose a policy explicitly when an operation can clamp a date, round precision or resolve an ambiguous clock label.

Dates, coordinates and evaluation limits

A civil date is not an instant. A local clock label needs an explicit offset or zone before it becomes a resolved boundary. Core calculations do not read the clock, use the machine's zone or download a database. Named zones can come from the optional zone-data package.

Spans include their start and exclude their end. Calendar days and months differ from coordinate durations across clock changes. Recurrence batches distinguish Complete from Limited; keep and resume the returned cursor to preserve COUNT, exclusions and pending interpretation. Never treat a limited batch as the whole answer.
